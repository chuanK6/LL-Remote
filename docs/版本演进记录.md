# LL远程版本演进记录

整理日期：2026-11-23（上海时区）。软件版本为 0.1.x，产品方案版本为 V1.3，两者分别管理。

本记录根据 CHANGELOG、开发与验收记录、各版本 JSON 和当前代码整理。项目拥有者已确认当前初版能够正常使用；下面保留各版本当时的验证范围，不把后续使用确认倒写成早期版本已经通过全部验收。

## 0.1.0：建立首个完整实现

建立 Tauri 2、Vue 3、TypeScript 和 Rust 桌面工程，实现设备页、收藏、账号、协助、首次向导、分应用设置、快速启动、连接历史与诊断。接入皎月连真实 WebSocket 协议、Sunshine 本机 API，以及 Moonlight 管理扩展。

建立独立 x86 EngineHost，加载原皎月连 DLL。设备资料与加密凭据分开，支持账号隔离、原子写入和备份恢复。连接支持取消、有限重试、首次 PIN 配对和完整画质快照；加入托盘、防休眠与自启动。早期交付同时使用 NSIS 与便携包，并随包携带固定 WebView2。

当时记录了前端 4 项、网页 8 项、Rust 9 项及隔离真实 API、环回配对、启动/解压/安装资源验证。**真实跨电脑串流未在该轮验证；0.1.1 用户问题说明原首用验证没有覆盖已有服务权限路径，因此原“完整首次使用通过”的说法已被撤回。**

原始依据：[开发与验收记录](开发与验收记录.md) 的“0.1.0 历史验证范围”，以及 `docs/validation/` 中 portable、installer、host、moonlight、bundle 等记录。

## 0.1.1：已有服务权限和向导导航

用户遇到创建/验证 Sunshine 账号时权限不足，需要到外部处理；向导没有取消入口，导航又被强制送回向导。

- LL 内部通过 UAC 运行限定到 Sunshine 服务启停的授权组件，不向权限组件传递密码，也不启动第二个主界面。
- 当时主界面与凭据存储仍使用原 Windows 用户权限；已有服务运行时等待其接口，验证已有账号不改服务配置。
- 通过 HTTPS 认证/welcome 响应判断账号状态，语言更新失败不再否决成功的账号创建。
- 增加取消向导和自由导航，离开后异步完成不再强制跳回。

按用户当时要求只修改并构建，没有运行测试或操作服务。取消按钮在 0.1.2 又按新的产品要求移除，不能据本版本说明恢复旧交互。

依据：[开发与验收记录](开发与验收记录.md) 的“0.1.1 修复记录：未测试”。

## 0.1.2：账号状态、主机识别、设置同步与系统 WebView2

处理已有 Sunshine 实际正常但 LL 无法确认身份/账号、第一步未完成而阻止皎月连登录的问题。普通用户无法读取系统子进程路径时，通过服务 PID、监听 PID、子进程信息和安装目录确认身份，并继续使用绑定的本机证书。

- Sunshine 已完成账号设置与 LL 是否持有 PIN 管理凭据分别判断，避免高级设置账号状态不同步阻断后续步骤。
- 登录、连接及接受控制前同步服务状态，后台刷新保留表单和前台错误；皎月连页面密码挑战显式显示。
- 移除取消按钮，改为离开向导后保留顶部恢复入口。
- Moonlight 高级设置与当前设备参数双向同步，修正 Qt 布尔值和 AV1 枚举，保留原配对及其他配置。
- 补齐 Qt OpenSSL TLS 插件，修复配对证书保存后为空 PEM 的问题，真实配对后重启读取应用通过。
- Sunshine 就绪检查覆盖管理、发现与 RTSP 端口；隔离测试检查整组端口并避开 Windows 保留端口。

本版本后续按用户要求改用**系统共享 Evergreen WebView2**，移除当前打包中的固定浏览器资源；用户 Data 位置保持。Windows Rust 库仅输出 `rlib`，避免额外生成不需要的 staticlib/cdylib。系统运行时实际启动、204 个既有数据文件保留及资源验证有记录；缺失系统运行时环境未实际测试。

当时的皎月连首用场景部分使用本机协议测试服务，不能当作跨电脑组网。原 Sunshine 系统服务只读测试因前置服务不存在而未完成；随包 Sunshine 独立账号流程及 Moonlight 真实环回配对有记录。

依据：[开发与验收记录](开发与验收记录.md)、[系统运行时记录](validation/system-webview2.json)。原文引用的 `validation/0.1.2.json` 当前工作区未找到，接手时不能据此虚构额外验证结果。

## 0.1.5：设备身份、DLL 加载、管理员启动和 PIN

- 设备按已确认 Sunshine UUID 合并重连记录，UUID 冲突保持独立；整理旧数据时保留 ID、昵称、收藏、壁纸、参数、有效凭据和历史引用。

- 自启动使用当前用户 HighestAvailable/InteractiveToken 计划任务，注册后回读验证，迁移失败恢复旧任务。

当时前端 14、网页 10、Rust 27 项通过；真实隔离 Sunshine/Moonlight 配对与重启复用授权通过。标准 Rust 测试忽略了 4 项原生场景，真实环回配对另行显式验证。双端实机与干净系统仍待验。

## 0.1.6：定位并修复具体 Wintun 故障

本机旧离线 Wintun 设备的持久 LUID 索引 32768 与运行时索引 32770 冲突。新接口拿到已占用索引后，NDIS 无法建立对应 GUID；管理员、x64、SYSTEM 和预加载驱动均复现，说明该问题不能简单归因于权限不足。

保存证据后，仅通过标准设备管理接口移除这条已确认的旧离线设备。随机 GUID 一次、原 SDK GUID 两次创建及收发会话成功，耗时分别为 265、172、188 毫秒。这是具体机器的已确认修复，不能套用到所有 Wintun 错误。

- 等待分为 VPN 配置、网卡初始化和服务就绪，保留合理的慢启动预算，兼容内核原拼写并直接报告真实网卡错误。
- 固定 SDK 哈希与内存布局校验后接入 Wintun 日志，保留 Windows 数值错误、设备问题代码和 NTSTATUS。
- Rust 核对当前 PID、操作时间和阶段，排除旧报告与清理日志；停止未确认时保留所有权和重试入口。

当时 Rust 34、前端 14、网页 10 项通过，另有 4 项原生场景按标记忽略。本机用户通过实际界面开启接受控制，SDK 运行、Sunshine HTTPS 200、设备 OK 和网卡 Up 均有记录。另一台电脑和重启后的恢复当时未覆盖。

依据：[0.1.6 记录](validation/0.1.6.json)、[虚拟网卡故障排查](虚拟网卡创建故障排查.md)。

## 0.1.7：组网地址、协助分享和 VPN 防火墙

- 高级设置显示本机组网地址；协助页提供识别码、连接密码和组网地址，齐备后支持全部复制，密码默认遮挡且不进入普通快照/日志。
- 同账号通过设备 ID 查询 `pcinfo`；访问码回包 IP 保持其客户端本机含义，提供手动地址、直连 /32 路由及邻居回退，排除本机候选并验证保存 UUID。
- 当时启动顺序为皎月连就绪 → VPN 限定防火墙 → Sunshine 就绪，失败按本次范围回滚；取得操作锁后重新读取偏好，防止关闭后旧任务重新开启。
- 按 Sunshine 程序、实际 Wintun 接口、本机地址及串流端口处理允许范围，保留其他公共网络及非串流端口阻止。

本机真实网卡、IP 分配、防火墙 DryRun/Apply/Restore 验证通过，恢复后原始 Block 一致、受管理规则为 0、网卡关闭且驱动未卸载。桌面自动验证停在 CDP 接口未连上，不能记为功能通过。

当时 Rust 45、前端 20、网页 10 项通过。防火墙作为关键启动门禁的顺序后来在 0.1.9 被替换。依据：[0.1.7 记录](validation/0.1.7.json)。

## 0.1.8：启动失败清理、输入草稿和设备顺序

接受控制日志显示首次失败后，后续只收到未启动状态却长时间等待。修复了可确认的状态清理缺口；首次原生提示没有保留，没有把它断言为某个具体网卡根因。

- 发起启动即记录未完成状态，失败后真正发送停止并等待确认；未确认时保留状态，下次先重试停止，避免仅清空变量。
- 缺少初始状态的 WebSocket 清理；仅收到未启动时不再无条件等待完整初始化预算，仍允许正常慢启动。
- 已有客户端组网连接时提示先断开，不自动中断；密码监听按值处理，草稿支持编辑/迟到请求/切页，并按确认账号隔离。
- 保持已有设备 ID 的列表位置，更新在线状态，新设备追加、删除移除；精简协助页布局。
- 本机旧宿主经过精确路径、哈希、父进程和服务状态核验后正常退出，未强杀、删驱动或数据；该清理不能当作新版串流验证。

当时 Rust 50 项通过、4 项忽略，前端 34 项通过，其中输入和账号隔离 16 项专项验证。依据：[0.1.8 记录](validation/0.1.8.json)。

## 0.1.9：防火墙警告不再关闭已经启动的服务

本机回归中，皎月连实际启动成功，随后防火墙准备失败使服务回滚。将防火墙作为关键启动门禁会让用户无法保持接受控制。

- 皎月连和 Sunshine 先启动，保存接受控制偏好后后台准备 VPN 限定防火墙。
- 防火墙或地址绑定尚未完成时单独报告警告，已经运行的服务不回滚；服务启动关键错误仍正常失败处理。
- 防火墙后台任务与停止/退出串行化，避免用户停止后迟到任务重新写规则；恢复规则需处理的问题与服务停止状态分开报告。
- 只有匹配规则等证据充分时才判断网络策略限制，保留固定错误码、操作阶段和 Windows 数值诊断。

当时 Rust 53 项通过、4 项忽略，前端 34 项通过。隔离行为测试使用真实 Sunshine、皎月连协议测试服务和不修改系统规则的防火墙响应替身，验证警告时服务保持、停止时关闭；不能记录成真实系统防火墙执行。

实际零 Block 的原生 Apply/Restore 当时未运行。依据：[0.1.9 记录](validation/0.1.9.json)。

## 0.1.11：断开、退出与会话窗口操作

- “断开本次连接”同时结束 Moonlight 串流并断开对应皎月连连接；完全退出处理本次运行使用的本机接受控制组件。

记录前端 34、网页 16、Rust 54 项通过。真实本机 Sunshine/Moonlight 环回串流验证窗口模式、鼠标、125% 缩放下悬浮球跟随、断开与退出；网络控制仍是隔离皎月连协议测试服务。真实两电脑组网与混合 DPI 多屏当时待验。

依据：[0.1.11 记录](validation/0.1.11.json)。
