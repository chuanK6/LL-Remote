# 连接流程与组网地址

本文说明连接行为与当前验证边界，记录日期为 2026 年 11 月 22 日（上海时区）。

## 首次连接与后续重连

两种入口都经过同一流程：建立皎月连组网 → 获取对方组网地址 → 确认 Sunshine 可达与主机身份 → 首次 PIN 配对 → 进入桌面。

| 入口 | 建立组网所需信息 | 对方地址的获取方式 |
| --- | --- | --- |
| 同账号设备 | 两端登录同一皎月连账号，在设备列表选择对方；无需另填对方连接密码 | 优先通过对方设备 ID 查询当前组网地址 |
| 识别码连接 | 填写被控端提供的识别码、连接密码和组网地址 | 使用提交的地址。已保存设备重连可复用原地址 |

首次 Sunshine 配对时，控制端显示四位 PIN，被控端显示输入 PIN 的弹窗。被控端输入控制端显示的 PIN 并确认后，控制端继续建立桌面会话。已保存且仍有效的配对证书会自动复用，后续重连通常不再输入 PIN。PIN 配对与皎月连采用哪一种连接入口无关。

“皎月连已连接”是皎月连连接层的状态；当前“对方 Sunshine 不可达”发生在 PIN 配对之前，需要先检查组网模式、对方地址和 Sunshine 服务。

## 组网地址

0.1.14 补充（2026-11-24）：本机正在接受控制且服务端组网 IP 与目标相同时，可开启「自动切换角色」。默认关闭时主窗口询问，批准后保存选项、暂停本机服务，再连接目标；拒绝停止本次连接。同账号地址若在连接后才取得，先结束本次客户端组网，再按同一逻辑会话重建一次。本机客户端 IP 排除及 Sunshine UUID 核对继续保留。

真实结束后先确认串流及客户端组网停止，再至少等待 3 秒核对无连接、无设置重连和账号/手动意图一致，才恢复接受控制。内部 Moonlight 重启不结束逻辑会话，也不启动恢复计时；手动停止或退出撤销恢复。0.1.14 运行测试由用户完成，该实现记录不代表双机验证已通过。

识别码连接的组网地址为必填项。请填写被控端协助页显示的组网地址。Sunshine 使用自定义端口时可以填写 `IP:端口`。

皎月连 v1.06 的 `conpc` 成功回包第 4 项及 `pclist` 尾部的 IP 都是**客户端本机 IP**，不能当作对方 Sunshine 地址。访问码连接的成功回包没有公开对方设备 ID，因此不能承诺每次只凭该回包就直接取得对端 IP。

同账号连接时，软件按设备 ID 查询 `pcinfo` 的组网映射，也可从已建立的 Wintun 接口发现对端地址。发现优先使用明确的直连 `/32` 主机路由，再补充该接口的邻居和有效下一跳。

连接成功后保存设备地址及已确认的 Sunshine UUID。后续重连继续验证 UUID，避免旧地址被分配给其他电脑后连错设备。

## 本机地址与全部复制

皎月连高级设置可以查看本机组网地址。协助页面开启本机接受控制后，显示：

- 访问码（识别码）；
- 当前连接密码，默认遮挡，可点击显示；
- 本机组网地址。

三项读取完整后，“全部复制”一次复制访问码、连接密码和组网地址。地址尚未取得时显示读取状态，不填入示例 IP。运行中的本机服务地址优先用于分享，避免把加入对方组网的客户端地址当成本机访问码对应地址。

## Sunshine 防火墙与验收边界

本机旧 0.1.6 环境已采集到与 Sunshine 程序对应的两条 Windows 自动创建的 Public 入站 Block 规则，分别作用于 TCP 和 UDP。它们是本机的直接阻碍因素；没有采集对端规则，不能断言对端也有相同规则，或将其认定为这次不可达的唯一原因。

新版实现按实际 Wintun 接口、本机组网 IP、Sunshine 程序路径和所需端口限定允许范围，同时保持其他公共网络和非远控端口的阻止行为。默认端口为 TCP `47984、47989、48010`，UDP `47998、47999、48000、48002`；自定义 Sunshine 基础端口按相同偏移调整。0.1.9 先启动皎月连和 Sunshine，再在后台准备限定防火墙访问。防火墙调整失败或本机地址尚未绑定时显示准确提示，不关闭已经运行的服务；远端连接仍取决于实际组网和防火墙状态。

**本机原生防火墙验证已通过。** 后续 Windows 实机测试成功创建 Wintun 网卡、启动收发会话并分配 IP，完成防火墙 DryRun 和 Apply；4 条受管理规则的程序、接口、本机地址及端口范围全部核对一致。TCP / UDP 非远控端口的 Public 阻止保留，Sunshine 管理网页端口不在允许项中。恢复后原来两条 Block 的过滤条件一致，受管理规则剩余 0，测试网卡已关闭，驱动未卸载。先前拒绝地址前缀的失败已由后续兼容修正和这次原生验证解决。证据见 [0.1.7 验证记录](validation/0.1.7.json)。

**桌面功能验收由用户完成。** 当前桌面自动测试停在 CDP 接口未连接，尚未进入功能测试；软件内接受控制的实际启停、全部复制的剪贴板效果，以及双机组网、PIN 配对和桌面串流均未由本轮桌面自动测试验证。详见 [0.1.7 验证记录](validation/0.1.7.json) 与[开发与验收记录](开发与验收记录.md)。
