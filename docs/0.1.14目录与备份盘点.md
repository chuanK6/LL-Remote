## 为什么会积累，为什么打包时另建目录

多轮修正一直保持 0.1.14 版本号，每轮都生成独立的干净打包目录；覆盖本机程序前又保存旧程序和 ZIP，再加上单独的 GitHub 发布材料，因此出现多个同名副本。部分打包产物与回退 ZIP 完全重复，交付结束后没有统一收束，造成积累。

release 中的程序可以直接运行。另建干净目录的限制仅针对制作 ZIP 或公开发布：release 的运行目录带个人 Data、凭据和配置，`scripts/package.ps1` 第 22 行附近会拒绝把含 Data 的现有输出目录作为干净打包目标；这不限制运行其中的 EXE。本轮已经将新 EXE 和干净 ZIP 同步回 release。

上述积累已按用户 11-25 新规定清理。release 是最终保留位置，临时包与替换前程序/ZIP只在本轮交付期间使用，完成后删除；发布记录留在当前 docs，不再保留完整发布工作目录。个人 Data 和原始诊断不属于本次删除范围。
